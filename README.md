# SafeBox Frontend

Веб-интерфейс SafeBox v2 — локального зашифрованного сейфа. Тёмная тема,
минимум лишних нажатий: инлайн-переименование по **F2**, ссылка добавляется
**Ctrl+V** в любом месте окна, файлы и папки — **drag&drop**.

Требования — UF-1…UF-13 из «ТЗ SafeBox v2» (Linqtab); контракт API — там же,
«REST API — контракт /api/v1».

## Скачивание из браузера прямо в сейф

Веб-страница не может «раскрыть» сейф как настоящую папку ОС, поэтому цель
«скачал в браузере → сразу в сейф» решается тремя способами:

- **Наблюдение за папкой** (Chromium: Chrome/Edge). «Импорт → 👁 Следить за
  папкой…» → выбрать «Загрузки» один раз. Всё новое, что браузер сохраняет
  туда, попадает в **открытую папку сейфа** автоматически через ~4–8 с (файл
  ждёт, пока размер стабилизируется; `.crdownload`/`.part` игнорируются;
  существующие файлы не трогаются). Состояние — чип 👁 в статусбаре
  (✕ — отключить). Хендл папки и отпечатки файлов переживают перезагрузку
  вкладки; отпечатки хранятся как хеши, а не имена — браузерный профиль не
  раскрывает, что попало в сейф. После блокировки наблюдение останавливается
  вместе с сессией. Оригинал в «Загрузках» остаётся — удалите его сами.
- **Ctrl+V картинки**: «Копировать изображение» на любой странице → Ctrl+V
  в окно SafeBox → файл в сейфе с именем «Вставлено дата время.png».
- **Перетаскивание** из панели загрузок браузера в окно.

## Повторный импорт и совпадения имён (UF-15)

Перед загрузкой партия сверяется с целевой папкой: `POST /import/plan` получает
пути и размеры файлов, но не содержимое.

- Совпадений нет — файлы уходят сразу; одноимённые папки сливаются.
- Есть — диалог «В папке уже есть N файлов с такими же именами»:
  «Заменить», «Пропустить» или «Решить для каждого файла» (у каждого две
  галочки «Из импорта» и «В сейфе» с размером и датой: только импорт — заменить,
  только сейф — пропустить, обе — оставить оба). Закрытие диалога отменяет
  весь импорт. Пропущенные файлы на сервер не передаются.
- Загрузка: первая часть multipart — `manifest` (JSON: `lastModified` файлов
  и `onConflict` решённых), дальше файлы. Тост: «Импортировано: N, заменено: K,
  пропущено: M».
- Тот же диалог спрашивает про занятые имена при перемещении (UF-14), только
  стороны называются «Из перемещаемого» и «В папке».
- Вставленные по Ctrl+V картинки получают имена с датой-временем — каждая
  вставка новая (как скриншоты).

## Ссылки и закладки (UF-20, UF-21)

Ссылки создаются только через `POST /links` (ярлыки `.url` фронт больше не
синтезирует; `.url`-файлы с диска импортируются как файлы, это делает сервер).
Дубликаты (тот же адрес без учёта регистра домена, «/» и `utm_*`) находит сервер.

- **Ctrl+V** в любом месте окна, кроме полей ввода: текст буфера — по строке на
  адрес (пробелы и пустые строки не в счёт), корректные http/https уходят одним
  запросом в открытую папку или открытые вложения. Все строки некорректны — тост
  «Это не ссылка»; часть — «Пропущено некорректных: N». Картинки и файлы из
  буфера, как и раньше, импортируются.
- **Перетаскивание** ссылки из браузера (`text/uri-list`, затем `text/plain`;
  строки `#` пропускаются) — в открытую папку; на карточку записи — во
  вложения записи (на карточку папки — в папку). От файлов и карточек сейфа
  отличается типами `DataTransfer` (`lib/dnd.ts`, `dragKind`).
- **Поле «Ссылка»** сверху: адрес → Enter → создано, поле пусто; без окон.
- Ответ: «Ссылка добавлена» / «Добавлено ссылок: N» (новые карточки подсвечены
  на 3 с); адрес уже есть — тост «Уже есть» с кнопкой «Показать» (открывает
  папку записи и выделяет её).
- **Закладки браузера**: «Импорт → Закладки браузера…», HTML-экспорт Chrome, Edge,
  Firefox (Netscape Bookmark). `lib/bookmarks.ts` разбирает `DL/DT/H3/A`
  через `DOMParser`: вложенные папки → `path` «Папка/Подпапка» (служебные
  «Панель закладок», «Bookmarks bar», «Other bookmarks» остаются в пути как
  есть), название закладки — имя ссылки (пустое или равное адресу — имя не
  передаётся, его подставит сейф); не http/https (`javascript:`, `place:`,
  `chrome://`, пустой адрес) пропускаются. Уходит в `POST /links` пачками по
  1000; тост «Закладки: создано N, уже было M, некорректных K».
- **Предпросмотр** (UF-21): пока у записей текущего листинга или результатов есть
  `previewPending`, список перечитывается раз в 2 с (`refetchInterval`), потом
  опрос сам прекращается; на карточке — маленький индикатор загрузки. «Обновить
  предпросмотр» в меню ссылки перечитывает карточку и миниатюру.
- **Настройки** (⚙ сверху): поповер с переключателем «Загружать предпросмотр
  ссылок» (`GET/PATCH /settings`) и пояснением, что это запрос к сайту с этого
  компьютера.
- Внешние ссылки открываются после подтверждения через
  `window.open(url, '_blank', 'noopener,noreferrer')`: окно приложения (WebView2)
  перехватывает новое окно и открывает адрес в системном браузере.

## Вложения и свойства (UF-14, UF-22)

- У любой записи могут быть вложения: бейдж «📎 N» на карточке, «Открыть
  вложения» в меню — они листаются как папка (`GET /entries?parentId=`), импорт
  идёт в открытые вложения.
- Перемещение: перетаскивание карточки (или всех выделенных) на карточку
  папки/записи или узел дерева; «Переместить…» в меню и панели выделения.
- Панель свойств справа (не модалка): «Свойства» в меню/панели выделения или
  `Alt+Enter`, следует за выделением, закрывается `Esc`/✕. Имя, адрес ссылки и
  описание правятся на месте, сохраняются при уходе из поля, `Esc` отменяет.

## Теги и фильтр (UF-16, UF-17, UF-18)

- Тег — `категория:тег`; имена сравниваются без учёта регистра, «ё» = «е».
  Каталог тегов — `GET /tags` в кэше TanStack Query, из него читают карточки, панель
  свойств, поля ввода и фильтр.
- На карточке — первые три тега и «+N» (прямые, потом бледные унаследованные).
  В панели свойств — теги записи по категориям; крестик снимает прямой тег, кнопка `↳`
  переключает его наследование; унаследованные бледные, «от: <запись>» в подсказке,
  без крестика, клик ведёт к записи-источнику. «Теги…» есть в меню карточки и в панели
  выделения (массово: добавить всем или снять у всех).
- Поле ввода тега — комбобокс: `↑↓` выбор, `Enter` подтвердить, `Tab` подставить вариант,
  `Esc` закрыть список. Нет тега — «Создать тег Y в категории X»; нет категории —
  «Создать категорию X и тег Y» с подтверждением тут же в поле (без модалки).
  Переключатель «Наследуется» (по умолчанию выключен) действует на добавляемый тег.
- Кнопка «Теги» сверху открывает экран управления: категории и теги со счётчиками,
  переименование на месте, перенос тега в другую категорию, удаление с подтверждением
  и числом записей, слияние при конфликте имён (409). Клик по тегу открывает фильтр.
- «Фильтр» рядом с поиском: выбор тегов (без создания), сочетание «И между категориями,
  ИЛИ внутри» / «Все И» / «Все ИЛИ», область «Весь сейф» / «В этой папке»
  (`within` = открытая папка или запись). Запрос — `GET /search?q&tags&match&within`;
  крошка «Фильтр: …», крестик, `Esc` или клик по папке сбрасывают фильтр.

## Стек

- Vite 5, TypeScript 5.5 (strict, `noUncheckedIndexedAccess`)
- React 18 + Tailwind CSS 3.4 (тёмная тема)
- TanStack Query 5 (кэш, инвалидация, статус загрузки)
- vitest + Testing Library; Playwright для e2e

## Запуск (dev)

Бэкенд — собранный `safeboxd` из репозитория safebox-backend:

```powershell
<path-to-safebox-backend>/build/msvc-debug/src/daemon/safeboxd.exe `
  --allow-origin http://localhost:5173 --allow-origin http://127.0.0.1:5173
```

```bash
npm install
npm run dev        # http://localhost:5173, /api -> 127.0.0.1:8900 (changeOrigin)
```

safeboxd на другом порту: `SAFEBOX_API=http://127.0.0.1:8901 npm run dev`.

## Сборка и встраивание

`npm run build` собирает `dist/`. Чтобы вшить фронт в `safeboxd.exe`,
сборка бэкенда запускается с `-DSAFEBOX_WEB_DIST=<путь к dist>` (см. README
бэкенда). CSP вшитого фронта: скрипты только `'self'`, инлайн-стили разрешены.

## Тесты

```bash
npm test           # vitest: api-клиент, пульс/автоблокировка, диалоги, главное окно, lib/*
npm run typecheck  # tsc --noEmit
npm run e2e        # Playwright
```

Глубокий e2e (создание сейфа → блокировка → повторный вход) создаёт настоящий
файл: `SAFEBOX_E2E=1 SAFEBOX_E2E_PATH=<путь нового сейфа>`. Уже поднятый стенд —
`SAFEBOX_E2E_URL=http://localhost:5174`; без скачанных браузеров Playwright —
`SAFEBOX_E2E_CHANNEL=msedge`.

## Контракт API

`src/api/types.ts` рукописный и синхронизирован с «REST API — контракт /api/v1»
в Linqtab (источник правды); ключи запросов TanStack Query — `src/api/queries.ts`.
Токен сессии — `sessionStorage`; медиа (`<img>`, `<video>`, скачивание) ходят
через HttpOnly-cookie `sbx_media`, токен в URL не попадает никогда. Любой
401 = мёртвая сессия → токен стирается, экран входа.

## Горячие клавиши

| Клавиши            | Действие                                    |
|--------------------|---------------------------------------------|
| `F2`               | инлайн-переименование (выбранной/наведённой карточки) |
| `Delete`           | удалить выделение (с подтверждением)        |
| `Ctrl+A`           | выделить всё в текущем виде                 |
| `Ctrl+клик` / `Shift+клик` / чекбокс | мультивыделение / диапазон |
| `←` `→` `Home` `End` | перемещение по карточкам (в лайтбоксе — по фото) |
| `Enter`            | открыть выбранное / подтвердить диалог      |
| `Alt+Enter`        | панель свойств выбранной/наведённой записи  |
| `Ctrl+V`           | адреса из буфера (по строке) → ссылки; картинка/файл → импорт в сейф |
| `Esc`              | закрыть верхний слой (меню, диалог, просмотр, панель свойств) → снять выделение → сбросить поиск |

Пока открыт диалог или просмотрщик, хоткеи галереи не срабатывают.

Добавление ссылки без отдельного окна: вставьте URL в поле «Ссылка ↵» сверху
или просто `Ctrl+V` в любом месте (подробнее — «Ссылки и закладки»).

## Присутствие и автоблокировка (UF-13)

Каждые 20 с уходит `POST /safe/heartbeat {active}`; активность — мышь,
клавиатура, навигация, а также длинные действия (импорт, воспроизведение
видео отмечают её сами). Из ответа `idleRemainingSec` считается локальный
дедлайн: за минуту до блокировки появляется предупреждение с посекундным
отсчётом, и любое движение мыши/клавиша (или «Остаться») сразу отправляет
пульс. Кнопка «🔒 Блокировка» в верхней панели стирает ключ на сервере; после
блокировки любой запрос даёт 401 и приложение само показывает экран входа.

Подтверждения — внутри страницы, не `window.confirm`: нативный диалог
замораживает JS вкладки, пульс перестаёт уходить, и через 2 минуты раздумий
сервер блокирует сейф как «закрытое окно».
